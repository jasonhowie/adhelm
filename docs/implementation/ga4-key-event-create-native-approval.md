# GA4 key-event CREATE native approval subject

`GA4_KEY_EVENT_CREATE_PLAN` is a fourth closed approval-host subject. It is
limited to one `Ga4KeyEventCreatePlannedAction`; it is not a generic direct-plan
or arbitrary-signature format. The Python builder and native parser both reject
unknown fields, noncanonical JSON, unsafe integer forms, scalar coercion,
unknown recovery behavior, and a challenge that outlives its plan.

The challenge contains the complete canonical action so both implementations
can reconstruct the same plan identifier, one GA4 Admin `CREATE` subplan,
zero incremental spend, fixed v1alpha POST target, no recovery action list, and
the explicit `RECONCILE_EXPORT_STOP_NO_REMOTE_COMPENSATION` disposition. It
binds the workspace, candidate and contract record digests, selection and
observation checkpoints, configuration/profile digests, sealed OAuth
association facts, inventory/state fingerprints, fixed request digests, plan
expiry, grantor, nonce, and host receipt configuration. It never supports an
opaque `DIRECT_PLAN` subject.

The first native decoder supports the shared `UTC` and `America/Chicago`
timezone subset. Other valid Python IANA zones fail before review until a
separately tested cross-language timezone contract is added. The decoder also
currently supports the fixed no-default-value request body; a decimal default
value is rejected rather than normalized through a different number parser. It
requires `ONCE_PER_EVENT` and exact ordered correspondence between the retained
compiler field names and the Boolean conversion bindings. A rehashed action
that relaxes counting or decouples those names is rejected before review. The
native parser also mirrors the compiler's closed sensitive-term boundary before
displaying an event or field name.

The deterministic local review tells the user that it is a zero-spend,
development-fixture-only GA4 CREATE request. It displays the configured OAuth
profile, safe native property and stream IDs, the safe event name, the fixed
once-per-event/no-default-value semantics, count transition, capacity and
duplicate facts, fixed egress, expiry, and the reconcile/export/stop
disposition. It binds but does not display customer source prose, native
path/body, OAuth subject, bearer, refresh token, or keyed marker. Its canonical
facts are signed through `review_digest`. The native review and receipt do not
claim current provider state, provider CREATE permission, a live validation,
or authority to execute an operation.

The receipt uses the existing P-256 domain-separated v1 format with the new
explicit receipt kind and direct fields: `grantor_ref`, `action_digest`,
`plan_digest`, and the single `subplan_digests` value. Existing pause and
policy bytes are unchanged. Native tests use ephemeral CryptoKit P-256 keys;
they do not invoke Keychain, LocalAuthentication, UI, XPC installation, or a
provider.

Python acceptance reparses the expected local challenge, verifies the receipt
against an independently supplied pin, and loads the exact earlier
`GA4_KEY_EVENT_CREATE_PLAN` record from the same verified ledger checkpoint.
It canonical-compares that retained action before issuing a direct grant. The
ledger history scan separately requires that the receipt claim source digest
names an earlier retained GA4 CREATE record with the identical action. This
prevents a receipt from being redirected to another plan record.

That acceptance path is structural only. It does **not** possess the local
fingerprint key and therefore does not authenticate the GA4 inventory HMAC or
prove current source state. The configured execution source validator performs
the keyed/current source check before receipt acceptance and again before OAuth
and kernel execution. A signed receipt remains evidence, not an installed host
trust root, provider permission, durable cross-process revocation barrier, or
remote mutation.

`tests/fixtures/swift-ga4-create-approval-receipt-v1.json` is a separate
public-only interoperability vector. It is generated by
`scripts/GenerateGa4KeyEventCreateApprovalReceiptVector.swift` from the native
production GA4 challenge, review, and receipt models with an ephemeral
software CryptoKit P-256 key. The fixture contains only the synthetic
challenge, review facts and digests, signed receipt, and public X9.63 key. The
Python production parser verifies it in `tests/test_ga4_approval_protocol.py`;
it does not rely on a Python-created signature. This adds no Keychain,
enrollment, OS authentication, or installed-host claim and leaves the legacy
Swift receipt vectors unchanged.
