# Rename to AdHelm (ticket O4.1)

Gate: [`release-0.1.0.md`](../release-0.1.0.md) ("Public tree"). Decision and rename table:
[ADR 0013](../adr/0013-open-source-release.md). The rename took an exclusive lock on the whole
tree and landed after every Wave 1-3 ticket.

## What changed

| Surface | Result |
| --- | --- |
| Distribution, import package, command | `adhelm` (`src/adhelm`, `[project.scripts] adhelm`, `uv build` produces `adhelm-0.1.0.tar.gz` and `adhelm-0.1.0-py3-none-any.whl`) |
| Error type | `AdhelmError` |
| Environment variables | `ADHELM_*` |
| Credential-store service names | `adhelm` and `adhelm.<kind>-v1` |
| Default data directory | Platform-native, below |
| Schema `$id` URIs | `https://aptsonic.com/adhelm/schema/...` |
| Domain-separation tags and record namespaces | `adhelm/...`, `adhelm.<kind>.v1`, `adhelm-local-*`, `adhelm_kernel_egress_permit`, `adhelm.macos-approval-host.receipt.v1` |
| Native bundle and service identifiers | `com.aptsonic.adhelm.*`, `adhelm-macos-approval-v1`, `AdHelmApprovalHost.app`, Swift package `AdHelmMacOSApprovalHost` |
| Version | `0.1.0` (was `0.1.0.dev0`) in `pyproject.toml`, `uv.lock` and `adhelm.__version__`, so the build artifacts carry the release version |
| Prose name | "Local Ad Control Plane" became "AdHelm" in the README, `.cursor` bootstrap and the docs that used it |

The schema URI and native identifier rows above reflect the owner decision of 2026-10-12
recorded in ADR 0013, which replaced the domain and reverse-DNS root this ticket first chose.

The rename is mechanical for names and carries no migration. A data directory, credential-store
entry or lock directory from a build before the rename is neither read nor moved. The owner
re-enrolls credentials (owner action 5 in the build plan).

## Default data directory

`config.default_data_dir()` is the only place that chooses the directory when `--data-dir` is
absent. It does not read `XDG_DATA_HOME`, matching the credential lock root.

| Platform | Directory |
| --- | --- |
| Linux and other POSIX | `~/.local/share/adhelm` |
| macOS | `~/Library/Application Support/adhelm` |
| Windows | `%LOCALAPPDATA%\adhelm` (the known-folder API, as the credential lock) |

The default is resolved lazily, in `cli.root(ctx)`, the single accessor for the data directory.
If the operating system cannot name the user directory, a command that needs local data fails
closed, reporting its full command name (for example `history status`, as `guarded(...)` names it),
with `DATA_DIRECTORY_UNAVAILABLE` (exit `2`) and a next action that names `--data-dir`, instead of
an `INTERNAL_ERROR`; `version`, `discover` and `schema` never touch
local data and still succeed. `tests/test_default_data_directory.py` covers the three platforms,
the refusal (including nested commands), that running `doctor`, `init` and `config show` with a
seeded invalid retired directory at `~/.local/share/<retired name>` neither reads nor changes it, and that an explicit `--data-dir` never consults the default.

## The retired-name check

`scripts/check_repository.py` fails on the retired command name (in any case, which covers the
old environment-variable prefix, the old error type and the old bundle identifiers) and on the
retired distribution name in its hyphenated and underscored spellings, in the contents or path of
any tracked or unadded, non-ignored file. It reports `path:line` only and never echoes
content. A file that is not UTF-8 text is searched as raw bytes and reported as `path: binary`.

The allowlist (`RETIRED_NAME_ALLOWLIST`) keeps the old names only where they record the past:

- ADRs 0001 and 0002 (all four files) and ADR 0013, which states the rename;
- the private build records the public export omits: `BUILD_PROMPT.md`, this build's plan, the
  Terra plan, `status.md`, `finishing-*` and the archived `*-validation*.json` run records (their
  digests describe artifacts that had the old names, so editing them would falsify the record);
- the check and its test.

`tests/test_check_repository.py` proves each spelling is caught, a path-only match is caught, the
allowlist is exact and never reaches source, tests, skills or the README, and that this repository
passes. The two tests that look for the old name on purpose spell it in parts
(`tests/test_skill_scenarios.py`), so they need no allowlist entry.

## Not changed

- Provider `connector_version` defaults (`0.1.0.dev0`) in the provider clients and their records
  are the connector's own version, not the package name; they keep their value so no recorded plan
  digest moves for a reason unrelated to the rename.
- The `development_version` key of the native artifact manifest keeps its name; it now carries
  `0.1.0`.
- Historical ADRs and the private build records above keep the old name by design.
